# NanoのハードウェアとTX2への適用範囲

## 概要・仕組み

JetsonではCPUとGPUが同じ装置上で動き、メインメモリや電源の余裕を共有します。LLMのGPUオフロードは、計算する場所を変える操作です。モデル全体の重み、KVキャッシュ、処理中の一時領域が不要になるわけではありません。

このため、CPU版が動くこととGPU版が安定することは別の問題です。GPUを有効にして装置ごと落ちる場合は、C++のビルドエラーと同じ分類にはできません。

## 対象Nanoと前提

**実機確認済みの保存情報**では、`aarch64`、カーネル`4.9.253-tegra`、L4TのBOARD表記`t210ref`、RAM表示約3.9Gです。rootは`mmcblk0p1`、媒体表示は29.7G。swapはzram4個で各495.5MiBでした。これらは特定時点の観測で、製品型番・キャリアボードの確定情報とは区別します。

GPU向け生成コードはQwen3構成でcompute_53/sm_53を確認しています。古いb5050構成には別のarch指定が残るため、[CUDAの説明](environment/cuda.md)を参照してください。

## 電源と運用

**ユーザー申告**では、GPU起動時に電源容量不足で落ちたため、ACアダプタへ切り替えるまではCPUだけで運用していました。電圧・電流・リセット原因を計測した記録はなく、対策完了も未確認です。アダプタの定格や接続方式を、この資料だけから推奨値として確定しません。

CPU経路を先に再現し、GPU起動や負荷試験は適合する電源と給電条件を確認してから別工程で扱います。クロック、nvpmodel、swap、タイムゾーンを再構築のついでに変更する手順は含めません。

## 確認方法

初期化後の確認は、値を読むだけの次の操作から始めます。

```sh
uname -a
cat /etc/nv_tegra_release
free -m
lsblk
swapon --show
```

保存値と異なった場合、すぐに設定を書き換えず、対象ボード・OSイメージ・媒体が正しいかを確認します。CPU推論のメモリ実測は [検証結果](../reference/validation-results.md) にあり、装置全体のRAM容量とプロセスRSSを区別しています。

## TX2へ移すとき

TX2の実機調査は行っていません。OSイメージ/flash指定、GPU arch、CPU命令、USBトポロジ、電源、メモリ、性能をNanoと同じ値にはできません。ソースやpatchを検討材料に使うことはできますが、Nano生成バイナリをコピーしてTX2の再構築完了とは判定しません。

TX2の数値を埋めるためだけの空テンプレートは設けず、この適用範囲を明示します。実測が得られた時点で、根拠とともに独立記事へ拡張します。
